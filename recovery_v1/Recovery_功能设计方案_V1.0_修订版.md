## 0. 修订说明

### 0.1 修订原则

修订遵循三条原则。第一，**只做 V1.0**：凡依赖体温、SpO₂、训练负荷、标签和问卷的逻辑一律移出，剩余信号必须能独立闭环。第二，**每个数字都可计算**：所有阈值集中在 `config.py`，文档与代码一一对应，不允许出现“偏高”“明显下降”这类不带数值的条件。第三，**连续、无悬崖**：子分和惩罚全部改为分段线性函数，相邻区间首尾相接，避免某个输入差 0.01 就让分数跳一档。

对外分数**保持 0–100 整数**。Apple Watch 的“准备指数”只作为产品形态参考（它是 0–10），本方案不改量程。

### 0.3 V1.0.2 输入更新

戒指端已能直接给出**每 5 分钟一个夜间 HRV 值**和**带起止时间的睡眠分期**，因此算法输入从"原始 RR 序列 + 30 秒一帧的分期"改为"5 分钟 HRV 记录 + 分期区间"。评分层（基线、子分、门控、趋势、不适风险）完全不变，变化只在输入和单晚指标提取。

| 项目 | V1.0.1 | V1.0.2 |
|---|---|---|
| HRV 输入 | RR/IBI 序列，算法自己算 RMSSD | 每 5 分钟一条记录，直接给 RMSSD |
| 睡眠分期 | 30 秒一帧的序列 | 区间列表（开始、结束、阶段） |
| 片段质量 | 由 RR 覆盖率和伪迹率推算 | 用设备给的 quality（缺省为 1），再加离群检测 |
| 佩戴覆盖率 | 外部输入 | 由有效 5 分钟记录自动推算 |
| 只有 RR 的设备 | — | 保留 `rr_adapter.py`，先把 RR 转成 5 分钟记录 |

本版采用以下默认假设，接入真实设备前需要确认：HRV 值为 RMSSD，单位毫秒（如果设备给的已经是 ln 值，设 `hrv_is_ln=true`）；"浅睡 / Light / Core"按 N2 处理；每条记录的心率、呼吸率、质量、体动均为可选。

## 1. 产品定义

### 1.1 定位

Recovery（恢复分）是一个**消费级、非医疗**的每日状态指标。它根据戒指夜间采集的心搏间期（RR/IBI）、睡眠分期和呼吸频率，把用户**今晚与自己的个人基线相比**的恢复程度，概括成一个 0–100 的整数，并给出颜色、一句话结论和行动建议。

它回答的问题是：“和我平时相比，今天身体准备得怎么样？”它不是诊断，不判断疾病，也不和其他人比较。

### 1.2 输出

每天早晨（夜间睡眠结束后）输出一条结果，包含：分数（0–100 整数，或在不满足条件时为空）、颜色档位（Green / Yellow / Red）、细分档位与标签、置信度（低 / 中 / 高）、触发的门控、主要影响因素（2–3 条）、不适风险等级与提示、训练建议、基线阶段。

### 1.3 分数、颜色与建议

| 分数 | 颜色 | 细分档 | 标签 | 建议 |
|---|---|---|---|---|
| 85–100 | Green | peak | 状态很好 | 适合高强度训练或重要任务 |
| 67–84 | Green | green | 恢复良好 | 按计划正常训练和工作 |
| 50–66 | Yellow | high_yellow | 恢复一般 | 可以活动，建议降低强度 |
| 34–49 | Yellow | low_yellow | 恢复偏低 | 以轻松活动为主 |
| 0–33 | Red | red | 需要休息 | 以休息为主 |

Yellow 封顶为 66、Red 封顶为 33，正好是 Yellow 区间和 Red 区间的上沿，所以**门控决定颜色上限，分数决定档内位置**，两者不会矛盾。

## 2. 设计原则

**个人基线优先。** 所有生理指标都转换为相对个人基线的 z 分数，不使用人群绝对阈值判断“好坏”（RESP 的绝对升高量是唯一的补充）。

**使用 Recovery HRV，而不是整晚平均 HRV。** 整晚平均会被觉醒、REM、体动和入睡初期的交感残留污染。Recovery HRV 只取高质量、稳定的 NREM 片段，并按睡眠阶段和时间位置加权。

**HRV 是核心，但不一票否决。** HRV 单独偏低最多到 Yellow；HRV 偏低并且 RHR 或 RESP 同时异常，才进入 Red 候选。

**防止“假性恢复”。** HRV 正常甚至偏高，但 RHR 或 RESP 明显升高时不能给 Green。

**RESP 只识别异常升高。** 呼吸频率比平时低不加分，只有升高才扣分。

**睡眠重要，但不能覆盖生理异常。** 睡得好不能把生理异常“洗白”；睡得差但生理正常时最多 Yellow。

**宁可不出分，也不出错分。** 数据不足时明确说明“数据不足”“睡眠过短”，不输出误导性数字。

## 3. 数据输入（V1.0.2）

#### 3.1 每晚输入

| 输入 | 必需 | 说明 |
|---|---|---|
| 5 分钟 HRV 记录 | 是 | 夜间每 5 分钟一条，字段见 3.2 |
| 睡眠分期区间 | 是 | 每条为（开始时间、结束时间、阶段），阶段写法见 3.3 |
| 上床时间 in_bed_start | 否 | 用于睡眠效率分母；缺失时用第一条分期的开始时间 |
| 症状 | 否 | 枚举 none / mild / moderate / severe，用户主动上报 |
| 外部睡眠分 | 否 | 0–100，已有睡眠评分时可直接替代睡眠子分 |

佩戴覆盖率不再作为输入，由算法根据有效 5 分钟记录推算（见 4.6）。

#### 3.2 5 分钟 HRV 记录字段

| 字段 | 必需 | 说明 |
|---|---|---|
| t_start | 是 | 窗口开始时间（ISO 8601），窗口长 300 秒 |
| rmssd | 是 | RMSSD，毫秒；`hrv_is_ln=true` 时为 lnRMSSD |
| hr_bpm | 否 | 窗口平均心率；缺失时当晚 RHR 子分跳过 |
| resp_brpm | 否 | 窗口呼吸频率（次/分）；缺失时 RESP 子分与门控跳过 |
| quality | 否 | 0–1 的信号质量，缺省为 1 |
| motion | 否 | 0–1 的体动强度，> 0.5 视为无效窗口 |

#### 3.3 睡眠阶段写法

| 内部阶段 | 可接受的写法 |
|---|---|
| Wake | wake、awake、w、清醒 |
| N1 | n1 |
| N2 | n2、light、core、浅睡 |
| N3 | n3、deep、sws、深睡 |
| REM | rem、快速眼动 |

阶段不区分大小写，也可直接用整数编码（Wake=0、N1=1、N2=2、N3=3、REM=4）。分期区间先按开始时间排序，去掉零长度区间；区间重叠时以后一条为准截断前一条。没有分期覆盖的时间视为未标注。

**V1.0 明确不使用**：体温/皮肤温度、SpO₂、训练负荷、生活标签（饮酒、出差等）、问卷、生理周期。数据模型中也不设这些字段。

## 4. Recovery HRV 计算

### 4.1 5 分钟记录校验

同一 t_start 的重复记录只保留一条。RMSSD 合法范围 3–250 ms，超出视为无效。对有效记录计算 lnRMSSD，与前后各 3 条有效记录的 ln 中位数比较，偏差超过 0.7 视为离群，质量置 0。心率超出 30–130 bpm 时只丢弃心率，RMSSD 保留。质量取设备给的 quality（缺省 1）；体动 > 0.5 时质量置 0。

### 4.2 分期映射

每个 5 分钟窗口与分期区间求重叠时长。被标注的时长不足窗口的 50% 时按 Wake 处理；否则取重叠最多的阶段为主导阶段。Wake 占比 > 20% 时按 Wake 处理。主导阶段占比 ≥ 80% 且没有 Wake 时记为"稳定"。

### 4.3 片段权重

片段权重 = 质量权重 × 阶段权重 × 时间权重 × 稳定性权重。

**质量权重** = 4.1 得到的窗口质量（RMSSD 无效或离群时为 0）。质量权重 ≥ 0.5 的片段计为“好片段”。

**阶段权重**：

| 阶段 | 稳定 | 混合 |
|---|---:|---:|
| N3 | 1.00 | 0.80 |
| N2 | 0.75 | 0.50 |
| N1 | 0.30 | 0.30 |
| REM | 0.20 | 0.20 |
| Wake | 0 | 0 |

**时间权重**：入睡后前 45 分钟 0.6；醒前 20 分钟 0；前半夜 0.95；中段（相对位置 0.4–0.6）1.0；后半夜 1.0。后半夜中，稳定的 N2/N3、质量权重 ≥ 0.8 且生理稳定的片段乘以 1.10（后半夜加权）。

**稳定性权重**：片段心率比当晚中位心率高 6 bpm 以上乘 0.6，高 10 bpm 以上乘 0.3；RESP 偏离当晚中位 3 次/分以上再乘 0.6。

### 4.4 聚合

Recovery HRV = 所有片段 lnRMSSD 的**加权中位数**，要求好片段 ≥ 6 个且其中 NREM ≥ 3 个，否则当晚 HRV 记为缺失。

Early HRV、Late HRV 分别取相对位置 < 0.5 和 ≥ 0.5 的 NREM 片段的加权中位数，各自至少 3 个片段，否则为缺失。

### 4.5 RHR 与 RESP

RHR = 好片段中 hr_bpm 最低的 6 个片段（约 30 分钟）的均值；设备不提供心率时 RHR 记为缺失。RESP = 当晚有效 RESP 片段的中位数，需要至少 36 个片段（约 3 小时），否则为缺失。

### 4.6 睡眠结构与佩戴覆盖率

睡眠结构直接从分期区间计算。入睡时刻为第一个非 Wake 区间的开始，醒来时刻为最后一个非 Wake 区间的结束。TST = 全部非 Wake 区间时长之和；WASO = 入睡到醒来之间的 Wake 时长；长觉醒 = 相邻 Wake 区间合并后时长 ≥ 5 分钟的次数；睡眠效率 = TST ÷（醒来时刻 − 记录开始），记录开始取上床时间与第一条分期中较早者，上限 1。

佩戴覆盖率 = 入睡到醒来期间，质量 ≥ 0.5 的有效 5 分钟窗口所覆盖的时长占比。缺失的窗口按未佩戴计。

## 5. 个人基线

### 5.1 窗口与统计量

基线**只使用今天之前的夜晚**，回看最多 60 天，取其中最近 30 个合格夜晚。每个指标（Recovery HRV、Early HRV、Late HRV、RHR、RESP、睡眠子分）分别计算中位数和 MAD。

### 5.2 sigma 收缩（解决冷启动）

样本少时 MAD 不可靠，因此用人群典型的“个体内日间波动”作为先验做收缩：

> sp = max(1.4826 × MAD, floor)
> sigma = sqrt((n·sp² + k·prior²) / (n + k))，k = 5

| 指标 | floor | prior |
|---|---:|---:|
| Recovery HRV（ln） | 0.12 | 0.20 |
| Early / Late HRV（ln） | 0.15 | 0.25 |
| RHR（bpm） | 2.0 | 3.0 |
| RESP（次/分） | 0.5 | 0.8 |
| 睡眠子分 | 8.0 | 10.0 |

先验只提供**波动幅度**，不提供绝对水平；中心值永远来自用户自己的数据。z = (今晚值 − 基线中位数) / sigma。

### 5.3 基线阶段

| 合格夜数 | 阶段 | 是否出分 |
|---:|---|---|
| < 3 | calibrating（校准中） | 否 |
| 3–6 | estimating（估算中） | 出分，置信度低，封顶 66 |
| 7–13 | trial（试用） | 出分 |
| 14–29 | provisional（暂定） | 出分 |
| ≥ 30 | formal（正式） | 出分 |

### 5.4 排除规则与新常态

以下夜晚不进入基线：TST < 210 分钟；症状为 moderate 或 severe；当晚被标记为基线离群（任一核心指标 |z| > 3，或不适风险 ≥ moderate）。

为避免原方案的循环依赖，“离群”标记在该夜**计算完成时**基于当时的基线确定，此后不再改动；今天的分数永远不影响今天自己的基线。

**新常态规则**：如果最近连续 7 晚以上都被标记为离群、且都没有症状，说明用户的生理水平发生了持续变化（作息、海拔、长期训练适应等），这些夜晚整体重新纳入基线，避免分数长期卡在低位。

## 6. 有效性与置信度

### 6.1 有效性（不满足则不出分）

| 条件 | 状态 | 前端文案 |
|---|---|---|
| 基线 < 3 晚 | calibrating | 正在建立你的个人基线 |
| TST < 180 分钟 | sleep_too_short | 睡眠时间过短，今日不计算恢复分 |
| 佩戴覆盖率（4.6）< 0.70 | insufficient_data | 夜间数据不足，今日不计算恢复分 |
| HRV 与 RHR 均缺失 | no_core_signal | 未获得有效心率数据 |

### 6.2 置信度

**低**（任一满足）：基线处于 estimating 阶段；Recovery HRV 缺失；好片段 < 6；TST < 240 分钟。低置信度触发 Yellow 门控 Y_LOW_CONF（封顶 66）。

**高**（全部满足）：基线为 formal；好片段 ≥ 12；佩戴覆盖率 ≥ 0.85；RESP 可用。

其余为**中**。

## 7. 子分数

### 7.1 HRV 子分

> S_HRV = clamp(70 + 18·z_HRV, 0, 95) + 后半夜修正

z = 0 对应 70 分（“平时水平”是良好而不是满分），+1.4σ 达到 95 的上限。上限设为 95，是为了给后半夜回升奖励和趋势加成保留空间，避免单靠 HRV 就顶到 100。

**后半夜修正**（两支互斥）：

负向修正：当 z_Late < −0.5 时，修正 = −min(6, 6 × (−0.5 − z_Late))。

回升奖励：仅当负向修正未触发，且 z_Early ≤ −0.5、dz = z_Late − z_Early > 0.5、z_RHR ≤ 0.5、RESP 严重度 r ≤ 1 时，奖励 = +min(3, 3 × (dz − 0.5))。

### 7.2 RHR 子分

> S_RHR = 100 − P_RHR

| z_RHR | P_RHR |
|---|---|
| ≤ 0.5 | 0 |
| 0.5–1.5 | 8 × (z − 0.5)，即 0 → 8 |
| > 1.5 | min(35, 8 + 14 × (z − 1.5)) |

RHR 低于基线不加分，只有升高才扣分；两段在 z = 1.5 处首尾相接。

### 7.3 RESP 子分

RESP 同时看相对升高（z）和绝对升高量 Δ（次/分），取更严重者：

> r = max(z_RESP, 等效 z(Δ))

| Δ（次/分） | 0 | 0.5 | 1.5 | 3.0 | 4.5 |
|---|---:|---:|---:|---:|---:|
| 等效 z | 0 | 1 | 2 | 3 | 4 |

| r | ≤ 0.5 | 1 | 2 | 3 | ≥ 4 |
|---|---:|---:|---:|---:|---:|
| P_RESP | 0 | 8 | 20 | 35 | 40 |

区间之间线性插值，S_RESP = 100 − P_RESP。这样既能防止基线波动很小的用户被轻微变化误判，也能在基线波动大的用户身上捕捉到绝对意义上的呼吸加快。

### 7.4 睡眠子分

> S_Sleep = 0.45·时长 + 0.20·效率 + 0.15·规律 + 0.10·连续性 + 0.10·睡眠债

**睡眠需求** = clamp(个人历史 TST 中位数, 390, 540)（无历史时 450 分钟）+ min(0.25 × 近 7 天睡眠债, 60)。不再依赖训练负荷。

| 分项 | 计算 |
|---|---|
| 时长 | TST / 需求，从 0.5 线性升到 1.0 对应 0→100 |
| 效率 | 睡眠效率 0.70→0.90 对应 0→100 |
| 规律 | 睡眠中点与个人习惯的偏差，0→120 分钟对应 100→0；无历史时 85 |
| 连续性 | WASO 20→90 分钟对应 100→0；第一次以后的每次长觉醒再扣 10 |
| 睡眠债 | 近 7 天累计欠债（每晚最多计 180 分钟），0→360 分钟对应 100→0 |

如果 App 已有成熟的睡眠评分（0–100），可以通过 `sleep_score_external` 直接传入并替代上式；未传入时使用上式计算。

## 8. 总分与趋势

### 8.1 原始加权分

> Raw = 0.45·S_HRV + 0.20·S_RHR + 0.25·S_Sleep + 0.10·S_RESP

某个子分缺失时，剩余权重按比例重新归一化（例如 RESP 缺失时，HRV 的权重变为 0.45 / 0.90 = 0.50）。HRV 与 RHR 同时缺失时不出分。

### 8.2 趋势修正

趋势使用最近 3 天内已出分的夜晚加上今天，修正范围限制在 [−8, +5]。

| 规则 | 条件 | 修正 |
|---|---|---|
| 生理下行 | 连续 3 晚 HRV 单调下降且 RHR 单调上升 | −5 至 −8（按幅度） |
| 呼吸上行 | 今天 r ≥ 1 且连续 3 晚 r 单调上升 | −4 至 −8 |
| 睡眠债 | 近 3 晚累计欠债 ≥ 120 分钟 | −3 至 −5 |
| 半衰 | 前 3 晚均为正常（Green 且无门控） | 负向部分减半 |
| 回升 | 4–7 天前 HRV z 均值 ≤ −0.5，今天提高 ≥ 0.5，且 RHR、RESP 正常 | +2 至 +5 |

### 8.3 最终分数

> Final = round_half_up( clamp( min(Raw + 趋势, 门控封顶), 0, 100 ) )

## 9. 门控与封顶

门控按“先 Red 后 Yellow”的顺序判定，取最严格的封顶值。Red 封顶 33，Yellow 封顶 66。**没有触发任何门控即具备 Green 资格**，分数达到 67 即为 Green。

| 级别 | 代码 | 条件 |
|---|---|---|
| Red | R_HRV_COMBO | z_HRV < −1.5 且（z_RHR > 1 或 r > 1.5） |
| Red | R_LATE_COMBO | z_Late < −1.5 且（z_RHR > 1 或 r > 1.5） |
| Red | R_RESP_COMBO | r > 3 且（z_RHR > 1 或有症状） |
| Red | R_MULTI_SEVERE | 以下 ≥ 2 项：z_HRV < −2，z_RHR > 2，r > 3，睡眠子分 < 35 |
| Red | R_SLEEP | 睡眠子分 < 35 |
| Red | R_SYMPTOM | 症状 moderate / severe |
| Red | R_ILLNESS | 不适风险 high |
| Yellow | Y_HRV | z_HRV < −0.75 |
| Yellow | Y_LATE | z_Late < −1 |
| Yellow | Y_RHR | z_RHR > 1 |
| Yellow | Y_RESP | r > 2 |
| Yellow | Y_SLEEP | 睡眠子分 < 60 |
| Yellow | Y_TST | TST < 300 分钟 |
| Yellow | Y_SYMPTOM | 症状 mild |
| Yellow | Y_LOW_CONF | 置信度低 |
| Yellow | Y_ILLNESS | 不适风险 moderate |

RESP 缺失时，所有依赖 r 的条件视为不满足。

## 10. 不适风险（无体温版）

去掉体温后，不适风险由以下积分累加：

| 信号 | 条件 | 积分 |
|---|---|---:|
| RESP | r > 2 / r > 3 | 2 / 3 |
| RHR | z > 1.5 或升高 ≥ 5 bpm / z > 2.5 | 2 / 3 |
| HRV | z < −1 / z < −2 | 1 / 2 |
| 后半夜 HRV | z_Late < −1.5 | 1 |
| 睡眠 | 睡眠子分 < 50 | 1 |
| 症状 | mild / moderate 或 severe | 2 / 3 |

| 总积分 | 等级 | 提示文案 |
|---:|---|---|
| 0–1 | none | 无 |
| 2–3 | mild | 部分夜间指标与平时略有不同，注意休息和补水。 |
| 4–5 | moderate | 夜间心率、呼吸等多项指标偏离你的平时水平，建议今天降低强度，多休息。 |
| ≥ 6 | high | 多项夜间生理指标明显偏离平时水平，建议今天以休息为主；如有不适，请咨询专业医生。 |

文案只描述“与平时不同”，不出现体温、血氧或任何疾病名称，符合消费级产品定位。

## 11. 解释与卡片文案

### 11.1 主要影响因素

每天展示 2–3 条影响因素。已触发的门控优先（同一类门控只展示一条），其次按子分对总分的偏离贡献排序。示例：“夜间静息心率高于平时”“后半夜 HRV 未能回升”“睡眠时长不足”“恢复型 HRV 高于平时”。

### 11.2 首页卡片示例

**Green 86**：恢复良好。HRV 处于你的平时水平，静息心率稳定，睡眠充足。按计划正常训练和工作。

**Yellow 66**：恢复一般。HRV 看起来正常，但夜间静息心率和呼吸频率高于平时。可以活动，建议降低强度。

**Red 33**：需要休息。HRV 明显低于平时，同时静息心率升高。今天以休息为主。

### 11.3 无分状态

校准中显示“已记录 N/3 晚，正在建立你的个人基线”；睡眠过短、数据不足时显示对应原因，并提示如何改善（例如佩戴更紧、充电时间避开夜间）。

## 12. 场景验证（Python 实现结果）

以下结果来自 V1.0.2 输入格式下的 `demo.py`（合成数据已改为 5 分钟 HRV 记录 + 分期区间），每个场景前先生成 40 晚正常数据，正式基线为 30 晚。数据为合成数据，用于验证逻辑，不代表真实人群分布。

| 场景 | 分数 | 颜色 | 关键门控 / 说明 |
|---|---:|---|---|
| 冷启动第 1–3 晚 | — | — | 校准中，不出分 |
| 冷启动第 4 晚 | 66 | Yellow | 置信度低，Y_LOW_CONF |
| 正常夜 | 66 | Yellow | Y_HRV；该合成夜 HRV 随机偏低，属抽样波动 |
| S1 正常高恢复 | 94 | Green | 无门控 |
| S2 假性恢复（HRV 略高，RHR +3，RESP +1.0） | 66 | Yellow | Y_RHR、Y_RESP；不适 moderate |
| S3 典型疲劳 | 33 | Red | R_HRV_COMBO；不适 moderate |
| S4 可能不适（轻微症状） | 33 | Red | 多个 Red 门控；不适 high |
| S5 睡眠差、生理正常（TST 290 分钟） | 66 | Yellow | Y_SLEEP、Y_TST；趋势 −3.6 |
| S6 后半夜恢复回来 | 82 | Green | 回升奖励生效 |
| S7 后半夜仍未恢复 | 33 | Red | R_HRV_COMBO、R_LATE_COMBO |
| 睡眠 < 3 小时 | — | — | sleep_too_short |
| 脱戴过多 | — | — | insufficient_data |
| HRV 缺失 | 66 | Yellow | 低置信度，权重重新分配 |
| 连续疲劳第 1–4 晚 | 66 / 66 / 33 / 33 | Y / Y / R / R | 第 4 晚趋势 −6.9；不适 high |
| 回升第 1–7 晚 | 33 / 59 / 65 / 66 / 86 / 91 / 94 | R→Y→G | 第 6 晚趋势 +3.4，第 7 晚 +5.0 |

S2 验证了“防假性恢复”：HRV 正常，但 RHR 与 RESP 同时升高，不给 Green。S5 验证了“睡眠差但生理正常最多 Yellow”。S6 与 S7 验证了后半夜修正的两个方向。连续疲劳序列验证了趋势规则会逐步加重，回升序列验证了基线排除、新常态和回升奖励能让分数平滑恢复。

## 15. 上线前需用真实数据校准的参数

合成数据只能验证逻辑。上线前建议用真实戒指数据（至少数十名用户、每人 4 周以上）校准以下参数：sigma 的 floor 与 prior；HRV 斜率 18 和中心 70；RHR、RESP 惩罚曲线；门控阈值（尤其 Y_HRV −0.75 与 R_HRV_COMBO −1.5）；不适风险等级阈值；分数分布（目标是正常人约 60–70% 的日子为 Green，Red 不超过 5–10%）。

---

## 16. 与 Apple 准备指数的关系

Apple Watch 的准备指数同样基于夜间 HRV、静息心率和睡眠，与个人基线比较，量程为 0–10。本方案在产品形态上参考这一思路，但**保持 0–100 整数量程**，以便表达更细的变化，并与现有睡眠分等指标保持一致。

## 17. 隐私与合规提示

恢复分为消费级健康参考，不用于医疗诊断。界面中应避免出现疾病名称；不适提示统一使用“与平时不同”“建议休息”“如有不适请咨询专业医生”等表述。

## 18. 不在 V1.0 范围内（V1.5 及以后）

体温 / 皮肤温度偏差；SpO₂；训练负荷与急慢性负荷比；饮酒、出差、时差等生活标签；主观问卷；生理周期基线；机器学习个性化权重。以上内容在本修订版的计算、门控和数据模型中均不出现。
